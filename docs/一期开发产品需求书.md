## 1. 文档目的

本文档是一期开发、技术选型、数据库设计、接口设计、任务拆分和测试验收的共同依据。前后端业务接口统一遵循 [`docs/API接口文档.md`](API接口文档.md)，本文件只规定一期 `P1` 接口和页面；API 文档中的 `P2`、`P3` 内容不属于一期开发和验收范围。

一期目标不是完成完整的学校教学管理平台，而是在 15 天内交付一个能够稳定演示和验收的核心学习闭环：

> 管理员准备学习内容 → 教师布置任务和客观题测验 → 学生完成学习和测验 → 系统记录结果 → 教师和学生查看反馈。

除本文档明确列入一期的内容外，其他功能均不属于一期开发和验收范围。需求变更必须经过评审，并同步更新本文件的变更记录。

## 2. 产品定位与一期目标

### 2.1 产品定位

本系统面向小学英语学习场景，通过 Web 页面提供基础学习内容、教师任务和客观题测验功能，帮助学生完成英语学习，帮助教师了解班级任务完成情况和测验结果。

产品长期规划可以包含家长观察、年级质量分析、积分榜单和生成式人工智能（AI）能力，但这些能力不属于本期交付目标。

### 2.2 一期目标

1. 建立单学校的基础组织和账号体系。
2. 提供管理员维护和发布学习内容的能力。
3. 提供词汇、语法、阅读三类基础学习内容；听力仅在已有合法音频资源时支持播放。
4. 提供教师布置学习任务和固定客观题测验的能力。
5. 提供学生学习、答题和查看个人结果的能力。
6. 提供教师查看授权班级任务完成情况和测验成绩的能力。
7. 保证管理员、教师和学生之间的数据访问边界正确。
8. 对账号、学习、任务、测验和关键管理操作形成可查询的记录。
9. 在 15 天内完成开发、测试、部署和一期验收。

### 2.3 一期成功标准

一期以“核心流程可用、权限正确、过程可追溯、能够通过验收”为成功标准，不以学生成绩提升、日活跃率或长期留存等运营指标作为本期上线门槛。

## 3. 一期范围与边界

### 3.1 一期范围

一期采用以下范围基线：

- 单学校部署；
- 三类角色：学校管理员、教师、学生；
- Web 用户端和管理端；
- 学习内容管理；
- 词汇、语法、阅读学习；
- 可选的基础听力播放；
- 学习任务；
- 固定题库客观题测验；
- 自动计分；
- 学习记录、答题记录、错题记录；
- 教师班级完成情况和成绩查看；
- 基础角色权限和数据隔离；
- 基础操作日志；
- 桌面浏览器和手机窄屏基础适配。

### 3.2 一期明确不包含的内容

以下内容不得作为一期开发任务或验收条件：

- 家长角色、家长端页面和家长与学生绑定；
- 年级质量管理员和教师质量分析；
- 多学校租户和跨学校管理；
- 教师创建内容、管理员审核内容的完整工作流；
- 教师名单批量导入和复杂导入异常处理；
- 网络内容抓取或网络公开内容自动采集；
- 复杂文件上传、音频转码和媒体资源管理；
- 主观题、人工批改和开放式回答；
- 生成式 AI 问答、AI 出题、AI 评分、AI 学习计划和 AI 报告；
- 可配置积分规则、积分流水纠错、防刷分；
- 周榜、月榜、学期榜和跨班级排名；
- 通知中心、短信、微信或其他站外推送；
- 报表文件导出；
- 学生转班、转学和多校区管理；
- 学校统一身份认证；
- 原生 App 和微信小程序。

### 3.3 范围控制原则

- 学习模块使用统一的“内容 + 练习”模型，不为词汇、语法和阅读分别开发独立业务引擎。
- 教师只能选择管理员已发布的内容，一期不实现教师内容审核链路。
- 一期优先支持单选题和判断题；其他题型必须经过评审后才能加入。
- 一期只记录学习和测验结果，不实现复杂能力模型。
- 一期只提供网页统计，不生成 Excel、PDF 或其他下载文件。

## 4. 用户角色与权限

### 4.1 角色定义

| 角色 | 角色标识 | 一期职责 |
|---|---|---|
| 学校管理员 | `admin` | 管理班级、教师和学生账号；维护和发布学习内容；查看基础汇总数据；记录关键管理操作 |
| 教师 | `teacher` | 查看授权班级；布置任务和客观题测验；查看班级任务完成情况、成绩和基础错题统计 |
| 学生 | `student` | 查看可用学习内容和本人任务；完成学习和测验；查看本人学习记录、成绩和错题 |

### 4.2 权限矩阵

| 功能 | 管理员 | 教师 | 学生 |
|---|---:|---:|---:|
| 登录和退出 | 是 | 是 | 是 |
| 修改自己的密码 | 是 | 是 | 是 |
| 重置其他用户密码 | 是 | 否 | 否 |
| 管理年级和班级 | 是 | 否 | 否 |
| 管理教师和学生账号 | 是 | 否 | 否 |
| 创建和编辑学习内容 | 是 | 否 | 否 |
| 发布和下架学习内容 | 是 | 否 | 否 |
| 查看全部已发布内容 | 是 | 是 | 是，仅限学习使用 |
| 创建学习任务 | 否 | 是 | 否 |
| 查看任务完成情况 | 是，基础汇总 | 是，授权班级 | 是，仅本人 |
| 创建固定客观题测验 | 否 | 是 | 否 |
| 完成测验 | 否 | 否 | 是，仅本人 |
| 查看个人学习记录 | 是 | 是，授权学生 | 是，仅本人 |
| 查看班级统计 | 是，学校范围 | 是，授权班级 | 否 |
| 查看其他学生详细数据 | 是，学校范围 | 是，授权班级 | 否 |
| 查看操作日志 | 是 | 否 | 否 |

### 4.3 数据权限原则

1. 管理员可以查看本学校范围内的基础管理数据和学习汇总数据。
2. 教师只能访问自己被授权班级及其学生的数据。
3. 学生只能访问自己的详细学习、任务和测验数据。
4. 学生不能通过修改 URL、请求参数或接口参数访问其他学生数据。
5. 教师不能访问未授权班级的数据。
6. 前端隐藏按钮不等同于权限控制，所有受保护操作必须在后端接口进行权限校验。
7. 当前一期为单学校系统，但所有核心业务数据仍应保留学校归属信息，便于后续扩展。

## 5. 核心业务流程

### 5.1 学校初始化流程

1. 系统初始化一个学校和管理员账号。
2. 管理员创建或维护年级、班级。
3. 管理员手工创建教师和学生账号。
4. 管理员为教师关联其负责的班级。
5. 管理员为学生关联其所属班级。
6. 用户使用初始账号登录。
7. 用户首次登录时修改初始密码。

一期可以使用初始化脚本准备演示数据，但正式功能必须支持管理员通过页面完成基础账号和班级维护。

### 5.2 内容发布流程

1. 管理员创建学习内容。
2. 管理员选择内容类型：词汇、语法、阅读或听力。
3. 管理员填写内容标题、正文和学习材料。
4. 管理员保存草稿并检查内容。
5. 管理员发布内容。
6. 已发布内容可以被教师选择并被学生学习。
7. 管理员可以下架内容；已下架内容不能新建任务，但历史学习记录保留。

一期不包含教师创建内容和管理员审核教师内容的流程。

### 5.3 教师布置任务流程

1. 教师进入自己授权的班级。
2. 教师选择已发布的学习内容。
3. 教师填写任务标题、任务说明、截止时间。
4. 教师选择一个或多个授权班级。
5. 教师发布任务。
6. 任务发布后，目标班级学生可以查看任务。
7. 学生完成任务后，系统记录完成状态和完成时间。
8. 教师查看任务完成数量、完成率和学生完成明细。

一期不支持任务复杂分组、分层布置、循环任务和自动提醒。

### 5.4 固定客观题测验流程

1. 教师创建测验并填写测验标题和说明。
2. 教师从题库中选择单选题或判断题。
3. 教师选择授权班级和截止时间。
4. 教师发布测验。
5. 学生进入测验并查看题目。
6. 学生提交答案。
7. 系统自动判定客观题正误并计算成绩。
8. 系统保存学生答题明细、得分和完成时间。
9. 学生查看自己的成绩和错题。
10. 教师查看班级成绩和基础错误统计。

一期默认每个学生对同一测验只允许提交一次。是否允许管理员或教师重新开放测验，作为技术设计阶段需确认的规则；未确认前不实现重测。

### 5.5 学生学习流程

1. 学生登录系统。
2. 学生浏览已发布的学习内容或进入任务列表。
3. 学生查看内容详情。
4. 学生完成学习内容或内容附带的客观练习。
5. 系统记录学习完成状态和完成时间。
6. 学生可以查看自己的学习历史、测验成绩和错题。

### 6.0 一期页面和接口基线

一期页面和业务接口以 [`docs/API接口文档.md`](API接口文档.md) 中标记为 `P1` 的项目为准。页面功能必须先映射到功能编号，再映射到 API 编号；没有对应 API、权限规则和验收用例的页面功能不得在一期开发中新增。

一期只提供 `admin`、`teacher`、`student` 三类角色，页面清单如下：

| 角色 | 页面 | 页面职责 | 主要接口领域 |
|---|---|---|---|
| 全部角色 | 登录页、首次改密、个人详情、退出登录 | 账号密码登录、首次修改初始密码、修改本人密码、查看非敏感个人信息 | `API-AUTH-001` 至 `API-AUTH-005` |
| 管理员 | 管理员首页 | 学校、年级、班级、账号、内容、任务和测验基础汇总；近期操作 | `API-DASH-001`、`API-LOG-001` |
| 管理员 | 学校/年级/班级管理 | 维护单学校、6 个年级、班级和学生归属 | `API-ORG-001` 至 `API-ORG-010` |
| 管理员 | 账号管理 | 创建、编辑、停用、重置教师和学生账号，维护教师班级关系 | `API-USER-001` 至 `API-USER-007` |
| 管理员 | 内容管理 | 创建、编辑、发布、下架词汇、语法、阅读和可选听力内容 | `API-CONTENT-003` 至 `API-CONTENT-006` |
| 管理员 | 题库管理 | 管理单选题、判断题及题目状态 | `API-QUESTION-001` 至 `API-QUESTION-004` |
| 管理员 | 基础统计和操作日志 | 查看学校基础汇总、登录/管理操作和权限拒绝记录 | `API-RECORD-007`、`API-LOG-001`、`API-LOG-002` |
| 教师 | 教师首页和班级列表 | 查看授权班级、待完成任务、测验和完成率 | `API-DASH-002`、`API-ORG-011` |
| 教师 | 内容选择 | 浏览管理员已发布内容并选用到任务或测验 | `API-CONTENT-001`、`API-CONTENT-002` |
| 教师 | 任务管理 | 创建草稿、发布、关闭任务，查看完成率和学生明细 | `API-TASK-001` 至 `API-TASK-007` |
| 教师 | 测验管理 | 创建单选题/判断题测验、发布、关闭、查看成绩和错误统计 | `API-QUIZ-001` 至 `API-QUIZ-008` |
| 教师 | 学生学习报告 | 查看授权学生学习记录、任务状态、成绩和错题 | `API-RECORD-005`、`API-RECORD-006` |
| 学生 | 学生首页和内容列表 | 查看待完成任务、学习入口和已发布内容 | `API-DASH-003`、`API-CONTENT-001` |
| 学生 | 内容详情和学习 | 阅读内容、播放可用听力资源、完成内容练习并记录学习状态 | `API-CONTENT-002`、`API-RECORD-002` |
| 学生 | 任务中心 | 查看所属班级任务、进入内容并提交完成状态 | `API-TASK-008` 至 `API-TASK-010` |
| 学生 | 测验和结果 | 完成客观题测验、查看本人得分、答题明细和错题 | `API-QUIZ-009` 至 `API-QUIZ-012` |
| 学生 | 学习记录和错题 | 按时间/内容类型查看本人的完成记录、成绩和基础错误统计 | `API-RECORD-001`、`API-RECORD-003`、`API-RECORD-004` |

一期明确不创建家长和年级质量管理员页面，不实现 `P2/P3` 接口对应的家长绑定、内容审核、积分榜单、通知中心、报表导出、批量导入、AI 能力和复杂质量分析。管理端的接口权限必须在后端执行，前端隐藏按钮不能替代权限校验。


### 6.1 账号与登录

#### FR-AUTH-01 登录

系统应支持管理员、教师和学生使用账号密码登录。

要求：

- 账号在本学校内唯一；
- 密码不能以明文形式保存；
- 登录成功后按照角色进入对应首页；
- 账号停用后不能登录；
- 登录失败时返回不暴露账号是否存在的提示。

#### FR-AUTH-02 首次修改密码

新建账号首次登录时必须修改初始密码，修改完成后才能进入系统其他功能。

#### FR-AUTH-03 修改密码

已登录用户可以修改自己的密码。修改时必须校验原密码和新密码规则。

#### FR-AUTH-04 管理员重置密码

管理员可以将教师或学生密码重置为初始密码，并将账号设置为下一次登录必须修改密码。

#### FR-AUTH-05 账号状态

管理员可以启用或停用教师、学生账号。停用账号不能登录，但历史学习和测验记录必须保留。

### 6.2 学校、年级和班级管理

#### FR-ORG-01 学校

一期系统只支持一个学校。学校基础信息应包含名称和状态，并作为核心业务数据的归属范围。

#### FR-ORG-02 年级

管理员可以查看、创建、编辑和停用年级。系统初始化时可以预置 6 个年级。

#### FR-ORG-03 班级

管理员可以查看、创建、编辑和停用班级。班级必须归属于一个年级。

#### FR-ORG-04 教师班级关系

管理员可以将教师关联到一个或多个班级。教师只能查看和操作其关联班级的数据。

#### FR-ORG-05 学生班级关系

管理员可以将学生关联到一个班级。学生只能查看所属班级布置给自己的任务。

一期不实现学生转班流程，但数据库关系设计应避免把班级名称直接写入学习记录，历史记录必须保留产生时的关联信息。

### 6.3 学习内容管理

#### FR-CONTENT-01 内容分类

系统至少支持以下内容分类：

- `vocabulary`：词汇；
- `grammar`：语法；
- `reading`：阅读；
- `listening`：听力，资源具备时启用。

#### FR-CONTENT-02 内容维护

管理员可以创建、查看、编辑和下架学习内容。

内容至少包含：

- 内容标题；
- 内容分类；
- 年级或适用范围；
- 学习正文；
- 配套资源地址或资源标识；
- 内容状态；
- 创建人和更新时间。

一期不实现网络抓取和复杂文件上传。内容可以使用系统内文本或已准备好的合法资源地址。

#### FR-CONTENT-03 内容状态

内容至少包含以下状态：

- `draft`：草稿；
- `published`：已发布；
- `offline`：已下架。

只有 `published` 状态的内容可以被教师选择创建新任务。

#### FR-CONTENT-04 内容练习

内容可以关联客观练习题。练习题只支持单选题和判断题，每道题必须有标准答案。

### 6.4 学习任务

#### FR-TASK-01 创建任务

教师可以创建学习任务，任务必须包含：

- 任务标题；
- 任务说明；
- 关联的已发布内容；
- 一个或多个授权班级；
- 发布状态；
- 截止时间；
- 创建时间和创建人。

#### FR-TASK-02 发布任务

任务创建后可以保存为草稿，也可以直接发布。只有已发布任务对目标班级学生可见。

#### FR-TASK-03 任务状态

任务至少支持以下状态：

- `draft`：草稿；
- `published`：已发布；
- `expired`：已过期；
- `closed`：已关闭。

系统可以根据截止时间展示过期状态，但是否禁止提交必须在技术设计阶段确定。建议一期截止后禁止首次提交。

#### FR-TASK-04 学生完成任务

学生可以查看分配给所属班级的已发布任务，并提交完成状态。重复打开任务不得重复产生完成记录。

#### FR-TASK-05 教师查看任务

教师可以查看自己创建的任务和授权班级的：

- 应完成学生数；
- 已完成学生数；
- 完成率；
- 学生完成明细；
- 未完成学生列表。

### 6.5 客观题测验

#### FR-QUIZ-01 题型

一期只支持：

- 单选题；
- 判断题。

不支持多选题、填空题、主观题和人工批改。

#### FR-QUIZ-02 题目维护

管理员或按技术方案确定的题库维护角色可以创建和编辑客观题。为控制一期范围，建议题目维护先由管理员完成。

每道题至少包含：

- 题干；
- 题型；
- 选项；
- 标准答案；
- 分值；
- 所属学习内容或知识分类；
- 状态。

#### FR-QUIZ-03 创建测验

教师可以从可用题目中选择题目，创建测验并关联授权班级。测验必须包含标题、题目、分值、目标班级和截止时间。

#### FR-QUIZ-04 提交测验

学生提交测验后，系统应：

- 校验学生是否属于目标班级；
- 校验测验是否处于可提交状态；
- 保存每道题的作答结果；
- 自动计算总分；
- 记录提交时间；
- 生成错题记录。

#### FR-QUIZ-05 查看测验结果

学生只能查看自己的答题明细、得分和错题。教师可以查看授权班级的成绩和基础错误统计。管理员可以查看学校范围内的汇总结果。

### 6.6 学习记录与结果反馈

#### FR-RECORD-01 学习记录

系统应记录学生对学习内容的学习行为，至少包括学生、内容、所属任务（如果有）、完成状态、首次开始时间、完成时间和更新时间。

#### FR-RECORD-02 测验记录

系统应记录学生参加测验的记录，至少包括学生、测验、所属班级、得分、总分、提交时间和完成状态。

#### FR-RECORD-03 答题明细

系统应保留学生每道题的作答结果，包括题目、学生答案、标准答案、是否正确、获得分值和作答时间（如果前端可提供）。

#### FR-RECORD-04 错题

错题由客观题判题结果产生。学生可以查看自己的错题，教师可以查看授权班级按题目或内容分类汇总的错误数量。

#### FR-RECORD-05 基础统计

一期只提供以下统计：

- 学生自己的学习完成记录；
- 学生自己的测验成绩；
- 学生自己的错题；
- 教师班级任务完成率；
- 教师班级平均分或成绩分布；
- 教师按内容分类的错误数量。

一期不实现复杂能力分布、学习画像、预测分析和教师质量评分。

### 6.7 管理员基础统计

管理员可以查看学校范围内的基础数量和汇总信息：

- 年级和班级数量；
- 教师和学生账号数量；
- 已发布学习内容数量；
- 任务数量和完成情况；
- 测验数量和参与情况。

一期不实现可配置报表、导出文件和跨学校统计。

### 6.8 操作日志

系统应记录关键管理和业务操作，至少包括：

- 登录成功和失败；
- 创建、修改、停用账号；
- 重置密码；
- 创建、发布、下架内容；
- 创建、发布、关闭任务或测验；
- 提交测验；
- 关键权限拒绝事件。

日志至少包含操作人、操作类型、目标对象、操作时间和结果。日志只要求管理员查看，一期不实现日志导出和复杂检索。

## 7. 业务规则

### 7.1 账号规则

1. 用户账号在学校范围内唯一。
2. 账号必须属于一个角色。
3. 学生必须关联一个班级后才能接收班级任务。
4. 教师必须关联至少一个班级后才能布置任务。
5. 停用账号不能登录，但历史记录不能删除。
6. 密码必须经过安全哈希处理，禁止明文保存。

### 7.2 内容规则

1. 草稿内容不能被教师用于创建已发布任务。
2. 下架内容不能被新任务选择。
3. 已存在的历史任务和学习记录不能因为内容下架而删除。
4. 一期内容由管理员负责创建和发布。
5. 内容资源必须来自自有、授权或专门准备的测试数据。

### 7.3 任务规则

1. 教师只能为自己授权的班级布置任务。
2. 教师只能选择已发布内容。
3. 学生只能看到所属班级的已发布任务。
4. 任务至少关联一个班级和一项学习内容。
5. 任务发布后，核心内容不应被无记录地修改；如需修改，建议关闭原任务后重新发布。
6. 学生完成任务后不得重复增加完成次数。

### 7.4 测验规则

1. 一期只允许单选题和判断题。
2. 每道题必须存在唯一标准答案和分值。
3. 每名学生对同一测验默认只能提交一次。
4. 已提交测验的成绩和答题明细必须保留。
5. 测验提交后自动计算成绩，不依赖教师人工批改。
6. 测验关闭或过期后的提交规则必须在开发第 1 天确认。

### 7.5 数据保留规则

一期不实现自动删除策略。账号停用、内容下架、任务关闭不会删除历史学习和测验记录。

## 8. 核心数据对象

本节不规定具体数据表名称，但为数据库设计提供业务对象边界。数据库设计应至少覆盖以下对象及其关联关系：

1. **学校**：学校名称、状态、创建时间。
2. **用户**：账号、密码摘要、姓名、角色、状态、学校归属、首次登录状态。
3. **年级**：年级名称、学校归属、状态。
4. **班级**：班级名称、年级归属、学校归属、状态。
5. **教师班级关系**：教师、班级和关联状态。
6. **学生班级关系**：学生、班级和关联状态。
7. **学习内容**：标题、类型、正文、资源、适用年级、状态、创建人。
8. **题目**：题干、题型、选项、标准答案、分值、内容分类、状态。
9. **学习任务**：任务标题、说明、内容、创建教师、状态、截止时间。
10. **任务班级关系**：任务和目标班级。
11. **学习完成记录**：学生、内容、任务、状态和完成时间。
12. **测验**：标题、说明、创建教师、状态、截止时间和总分。
13. **测验题目关系**：测验、题目、题目顺序和测验分值。
14. **测验班级关系**：测验和目标班级。
15. **学生测验记录**：学生、测验、班级、状态、得分和提交时间。
16. **学生答题记录**：学生测验记录、题目、学生答案、判题结果和得分。
17. **操作日志**：操作人、操作类型、目标对象、时间和结果。

数据库设计时必须重点保证：

- 业务记录具备学校归属或可通过关联关系确定学校归属；
- 学生、教师、任务和测验之间的关系可追溯；
- 历史记录不依赖当前账号或内容名称才能解释；
- 任务、测验和记录具备创建时间、更新时间等审计字段；
- 关键业务查询具备必要的索引设计；
- 账号、班级和题目等基础对象具备合理的唯一性约束。

## 9. 非功能需求

### 9.1 安全与权限

- 所有受保护接口必须进行登录认证。
- 所有业务查询和写操作必须进行角色与数据范围校验。
- 密码必须使用安全哈希算法保存。
- 接口错误不能泄露密码、完整用户信息或其他学生的学习明细。
- 前端不得将权限校验作为唯一安全措施。
- 关键管理操作应写入操作日志。

### 9.2 可用性

- 核心页面应提供加载中、空数据、提交成功和失败提示。
- 表单字段应进行必要的必填和格式校验。
- 测验提交前应有明确的提交操作提示。
- 已完成任务和已提交测验应有明确状态展示。

### 9.3 兼容性与响应式

一期以主流桌面浏览器为主要使用环境，并保证手机窄屏下核心流程可以使用：

- 登录；
- 浏览内容；
- 查看任务；
- 完成测验；
- 查看结果。

一期不承诺覆盖全部浏览器版本、平板型号和无障碍标准，但页面结构不得依赖固定大屏宽度才能完成核心操作。

### 9.4 性能

在项目验收测试数据规模下：

- 普通列表页面应在合理时间内完成加载；
- 提交测验后应能正常返回结果；
- 常用列表和详情接口不应执行明显无条件的全表扫描；
- 页面操作不能因一次请求加载全部学校历史明细而失去可用性。

具体并发量和性能压测指标在技术方案阶段根据部署环境确认。一期不以大规模生产并发作为验收目标。

### 9.5 数据备份与部署

技术方案至少应明确：

- 数据库初始化和迁移方式；
- 应用配置和敏感信息管理方式；
- 数据库备份方式；
- 测试环境和验收环境；
- 日志查看方式；
- 出现故障后的恢复步骤。

## 10. 测试与验收标准

### 10.1 功能验收

1. 管理员可以创建和维护年级、班级、教师和学生。
2. 管理员可以启用、停用和重置基础账号。
3. 三类角色可以登录；首次登录必须修改初始密码。
4. 管理员可以创建、编辑、发布和下架学习内容。
5. 教师只能查看授权班级，并可以使用已发布内容创建任务。
6. 教师可以创建单选题和判断题测验，并指定授权班级。
7. 学生可以查看所属班级任务并完成学习。
8. 学生可以提交测验，系统可以自动计分并记录答题明细。
9. 学生可以查看自己的成绩、学习记录和错题。
10. 教师可以查看授权班级的完成率、学生成绩和基础错误统计。
11. 管理员可以查看学校范围内的基础汇总数据和关键操作记录。
12. 桌面浏览器和手机窄屏可以完成核心流程。

### 10.2 权限验收

必须至少验证以下场景：

- 学生不能查看其他学生的学习记录和测验明细；
- 学生不能通过修改学生编号访问其他学生数据；
- 教师不能查看未授权班级；
- 教师不能为未授权班级创建任务或测验；
- 教师不能使用未发布内容创建任务；
- 停用账号不能登录；
- 非管理员不能重置其他用户密码；
- 非登录用户不能访问受保护接口；
- 下架内容不能用于新建任务；
- 历史记录在账号停用或内容下架后仍可追溯。

### 10.3 数据验收

- 任务完成记录包含学生、任务和完成时间；
- 测验记录包含学生、测验、得分和提交时间；
- 答题记录可以还原学生每道题的作答结果；
- 错题可以由答题记录准确得到；
- 教师统计结果与明细数据一致；
- 关键管理操作可以查询到操作人、操作对象和时间。

### 10.4 验收不包含的内容

家长端、年级质量分析、积分榜单、通知、报表导出、AI 功能、内容审核流、多学校租户和原生移动端不属于一期验收范围。

## 11. 15 天实施计划

本计划按至少两名开发人员、测试与开发并行、已有可用测试内容估算。

|---|---|---|
| 第 1 天 | 需求冻结和技术设计启动 | 技术选型结论、页面清单、数据模型草案、测试数据约定 |
| 第 2 天 | 项目骨架 | 前后端项目、数据库迁移、基础布局、开发环境 |
| 第 3 天 | 登录与鉴权 | 登录、退出、首次改密、角色鉴权 |
| 第 4 天 | 组织与账号 | 学校、年级、班级、教师、学生基础管理 |
| 第 5 天 | 内容管理 | 内容 CRUD、分类、状态和发布 |
| 第 6 天 | 学生学习 | 内容列表、详情、学习完成记录 |
| 第 7 天 | 任务管理 | 教师选择内容、指定班级、发布任务 |
| 第 8 天 | 测验管理 | 题目、测验、单选题和判断题 |

## 12. 技术设计前必须确认的事项

以下事项必须在第 1 天完成确认，否则会影响数据库和接口设计：

1. 一期是否采用单学校、单部署环境。
2. 词汇、语法、阅读内容的最终字段和测试数据。
3. 是否具备合法可用的听力音频；没有则关闭听力入口。
4. 客观题是否只支持单选题和判断题。
5. 测验是否只允许提交一次。
6. 任务或测验过期后是否禁止提交。
7. 教师与班级是多对多关系，学生一期是否严格只属于一个班级。
8. 内容下架后历史任务和学习记录的展示规则。
9. 管理员基础统计页面的具体指标。
10. 测试环境、验收环境和部署方式。

未在上述清单中确认的功能，不得在开发过程中自行扩展到一期。

## 13. 二期规划方向

一期验收通过后，再根据试用反馈决定二期优先级。候选功能包括：

- 家长端和家长—学生绑定；
- 年级质量管理员和年级数据分析；
- 教师创建内容及管理员审核；
- 批量导入账号；
- 积分流水、积分规则和班级榜单；
- 周榜、月榜和学期榜；
- 通知中心和站外推送；
- 报表导出；
- 多学校租户；
- 主观题和人工批改；
- 听力资源管理；
- AI 学习问答、AI 出题、AI 评测和个性化学习。

二期功能不能反向成为一期开发和验收的前置条件。

MacOS 使用 sdkman 安装 JDK 17 的示例：

```bash
sdk install java 17.0.20-tem
sdk use java 17.0.20-tem
```

## 2. 快速开始

### 2.1 启动本地依赖（MySQL + Redis）

```bash
docker compose -f deploy/docker-compose.yml up -d
docker compose -f deploy/docker-compose.yml ps     # 等到 mysql 显示 healthy
```

首次启动会自动执行 `database/migrations/V3.31.0__smart_admin_baseline.sql`，创建 `smart_admin_v3` 库（44 张表）。

```bash
# 确认建库成功
docker exec ael-mysql mysql -uroot -pSmartAdmin666 -e "SHOW TABLES FROM smart_admin_v3;" | head
```

> 初始化脚本只在数据卷为空时执行。修改迁移脚本后需要重新初始化：
> `docker compose -f deploy/docker-compose.yml down -v`（会删除本地数据，慎用）。

### 2.2 启动后端（端口 1024）

```bash
cd backend
mvn -DskipTests clean package
java -jar sa-admin/target/sa-admin-dev-3.0.0.jar
```

开发期也可以用：

```bash
cd backend
mvn -pl sa-admin -am spring-boot:run
```

启动成功的标志：

```text
Tomcat started on port 1024 (http) with context path '/'
Started AdminApplication in 6.166 seconds
```

接口文档（Knife4j）：<http://127.0.0.1:1024/doc.html>，OpenAPI JSON：<http://127.0.0.1:1024/v3/api-docs>。

### 2.3 启动前端（端口 8081）

```bash
cd frontend
fnm use            # 或 nvm use，读取 .node-version
pnpm install
pnpm dev
```

访问 <http://localhost:8081/>。

### 2.4 演示账号

脚手架初始化脚本自带以下账号（`t_employee` 表），一期开发只用于验证基础设施：

| 账号 | 说明 |
|---|---|
| `admin` | 超级管理员，功能最完整，建议先用它验证登录与后台菜单 |
| `huke` / `zhuoda` / `shanyi` 等 | 脚手架示例账号，一期可直接忽略或后续清理 |

一期上线前必须按 `docs/一期开发产品需求书.md` 重建 `admin` / `teacher` / `student` 三类角色与测试账号，**不得使用真实未成年人信息**。

## 3. 配置说明

### 3.1 配置文件位置

后端的配置按 profile 分目录存放，构建时把 `src/main/resources/${profiles.active}/` 的内容拷贝到 `target/classes` 根目录：

| 文件 | 作用 |
|---|---|
| `backend/sa-admin/src/main/resources/dev/application.yaml` | 应用名、端口、日志目录、profile |
| `backend/sa-base/src/main/resources/dev/sa-base.yaml` | 数据源、Redis、Sa-Token、文件上传、跨域等通用配置 |
| `frontend/.env.development` | 前端环境变量（标题、后端地址） |
| `frontend/.env.production` | 生产构建使用的后端地址 |

### 3.2 dev profile 关键配置

| 配置项 | 值 |
|---|---|
| 后端端口 | `1024` |
| MySQL | `127.0.0.1:3306/smart_admin_v3`，`root` / `SmartAdmin666` |
| Redis | `127.0.0.1:6379`，`database: 1` |
| 日志目录 | `${localPath:${user.home}}/logs/smart_admin_v3/sa-admin/dev` |
| 上传目录 | `${localPath:${user.home}}/smart_admin_v3/upload/` |
| 跨域 | `access-control-allow-origin: '*'`（仅开发环境） |

`localPath` 是用于覆盖路径根的可选变量，不传时默认落到当前用户主目录：

```bash
# 把所有运行时产物的根目录收敛到仓库内的 .runtime/（已被 .gitignore 忽略）
java -DlocalPath="$PWD/.runtime" -jar backend/sa-admin/target/sa-admin-dev-3.0.0.jar
```

Linux 或容器环境仍可传 `-DlocalPath=/home` 恢复脚手架原行为。

### 3.3 前端到后端的调用方式

前端通过 `frontend/src/lib/axios.ts` 的 `baseURL: import.meta.env.VITE_APP_API_URL` 直连后端，默认 `http://127.0.0.1:1024`，依赖后端的 CORS 放行，**没有走 Vite 代理**。详见第 4.5 节。

## 4. 初始化阶段发现并修复的问题

以下问题都已在本仓库修复，记录在此避免重复踩坑。

### 4.1 `.gitignore` 误伤后端测试目录（已修复）

上游模板的 `.gitignore` 含有一条 `test/` 规则，会静默忽略：

- `backend/sa-admin/src/test/`
- `backend/sa-admin/src/main/resources/test/`
- `backend/sa-base/src/main/resources/test/`

后果是测试代码和 test profile 的配置无法入库，且 `git status` 不会有任何提示。已重建根目录 `.gitignore`，删除了 `test/`、`*.jar`、`*.zip` 等宽泛规则，改为按用途分类的精确规则。

### 4.2 Maven 资源过滤失效，profile 变成字面量（已修复）

现象：构建产物 `BOOT-INF/classes/application.yaml` 中 `spring.profiles.active` 是字符串 `'@profiles.active@'`，日志目录也随之变成 `.../sa-admin/@profiles.active@/`。

两个叠加原因，都在根 `pom.xml`：

1. 本项目未继承 `spring-boot-starter-parent`，`@...@` 不是 Maven 默认过滤分隔符，需要显式声明 `<delimiter>@</delimiter>`；同时必须 `useDefaultDelimiters=false`，否则 yaml 里的 Spring 占位符（`${user.home}`、`${project.name}`）会被 Maven 提前替换掉。
2. 第三个 `<resource>` 块的 `<include>*.*</include>` 同样匹配 `application.yaml`，而它在 `filtering=true` 的资源块之后执行，会用未过滤的原文覆盖已过滤的结果。

修复后 `target/classes/application.yaml` 正确输出 `active: 'dev'`，且 `${...}` 形式的 Spring 占位符保持原样。

### 4.3 dev 配置写死 `/home`，macOS 无法启动（已修复）

`dev` profile 的 `log-directory` 与 `file.storage.local.upload-path` 原先都以 `/home` 开头。macOS 的 `/home` 是只读挂载点，会导致启动即失败。

已改为 `${localPath:${user.home}}`，macOS 默认落到用户主目录，Linux/CI 仍可用 `-DlocalPath=/home` 覆盖。`test` / `pre` / `prod` 三个 profile 的路径未改动，属于部署环境配置，由部署阶段确认。

### 4.4 pnpm 拦截安装脚本导致 esbuild 缺失（已修复）

pnpm 10 起默认禁止依赖执行安装脚本，`esbuild` 的原生二进制因此没有被安装，`pnpm dev` 和 `pnpm build:prod` 都会直接失败。

已在 `frontend/pnpm-workspace.yaml` 用 `allowBuilds` 显式声明：

| 依赖 | 决定 | 原因 |
|---|---|---|
| `esbuild` | `true` | Vite 依赖的原生二进制，不放行则构建失败 |
| `vue-demi` | `true` | 安装时需按 Vue 版本切换入口文件 |
| `core-js`、`es5-ext` | `false` | 安装脚本只打印提示信息，无实际作用 |

必须把 `false` 也写出来：只要存在「未声明的构建脚本」，pnpm 就会以非 0 退出码结束，`pnpm build:prod` 会因为前置的依赖校验而失败。

### 4.5 待确认偏差（尚未修改）

以下两点是脚手架现状与 `docs/技术架构.md` 的偏差，属于设计决策，**未在初始化阶段擅自改动**：

1. **接口前缀**：架构文档第 9.1 节要求接口统一以 `/api`（或 `/api/v1`）开头，脚手架现状是 `server.servlet.context-path: /`，接口直接是 `/login`、`/category/tree` 这样的路径。是改 context-path、加统一前缀，还是修订架构文档，需要技术负责人定稿。
2. **Vite 代理配置无效**：`frontend/vite.config.ts` 中的 `proxy` 被错误地嵌套在 `server.server.proxy` 下，Vite 不会读取，实际是无效配置。当前开发环境靠「前端直连 1024 端口 + 后端 CORS 全放行」工作，功能上没问题，但架构文档描述的「Vite 代理 `/api` 到 Spring Boot」并未落地。如果要按架构文档收口，需要同时修 `vite.config.ts`、`.env.*` 的 `VITE_APP_API_URL` 和后端前缀。

### 4.6 统一响应结构以脚手架为准

架构文档第 9.3 节给出的示例是 `{code, message, data, traceId}`，脚手架实际返回：

```json
{ "code": 10001, "level": "system", "msg": "...", "ok": false, "data": null, "dataType": 1 }
```

按架构文档「具体字段名以脚手架既有规范为准，新模块不应同时引入第二套响应格式」的要求，一期沿用脚手架格式，新业务模块不要另造一套。

## 6. 常见问题

| 现象 | 原因与处理 |
|---|---|
| `pnpm` 报 `requires at least Node.js v22.13` | 当前 shell 的 Node 还是 18。执行 `fnm use` 读取 `.node-version`，或用 `fnm exec --using=22.23.2 pnpm ...` |
| 后端启动报数据库连接失败 | 先确认 `docker compose ps` 中 mysql 为 `healthy`；首次启动建库需要约 20–40 秒 |
| 端口 3306 / 6379 被占用 | 同机其他项目（如 `maker-learning`）的容器可能正占用端口，先停掉再启动本项目 compose |
| `Operation not permitted` 写 `~/.m2` | 沙箱或权限限制，确认 Maven 本地仓库目录可写 |
| 前端页面能打开但接口 404/跨域 | 确认后端已在 1024 端口启动，且 `frontend/.env.development` 的 `VITE_APP_API_URL` 指向正确地址 |
